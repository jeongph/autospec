# autospec 에이전트 지침

## 너의 목표
.autospec/domain/ 폴더의 문서에 서술된 비즈니스 규칙을 코드가 완벽히 만족하도록 하라.
.autospec/eval.md의 모든 기준을 통과할 때까지 작업하라.

## 작업 순서

1. .autospec/common/ 의 모든 문서를 읽고 기술/인프라 규약을 파악한다
2. .autospec/domain/ 의 모든 문서를 읽고 비즈니스 규칙을 파악한다
3. src/ 소스 코드를 읽고 현재 구현 상태를 파악한다
4. 도메인 규칙과 구현 사이의 간극(gap)을 목록으로 정리한다
5. 간극을 메우기 위해 코드를 수정하고 테스트를 작성한다
6. 빌드하고 테스트를 실행하여 검증한다
7. 서버를 띄우고 API를 호출하여 실제 동작을 검증한다
8. .autospec/eval.md 기준으로 결과를 평가한다

## 수정할 수 있는 것
- src/main/java/** (서비스 코드)
- src/test/java/** (테스트 코드)

## 건드리면 안 되는 것
- .autospec/** (사람의 영역)
- build.gradle, settings.gradle
- application.yaml
- gradlew, gradle/

## 제약
- 한 사이클 제한시간: 10분
- 기존 public API 시그니처를 함부로 바꾸지 말 것
- 확신 없는 큰 변경보다 작은 확실한 변경을 우선하라
- 새 파일을 만들 수 있다 (DTO, 예외 클래스 등)

## 커밋 규칙
- 작업이 끝나면 반드시 git commit을 수행하라
- 변경 사항이 없으면 커밋하지 마라
- 커밋 메시지는 한글로 작성하되, type prefix는 영문을 사용한다 (예: feat: 할일 삭제 기능 추가)
- 한 사이클에 하나의 커밋만 생성하라
